This repo is the companion to a blog post I wrote about exactly that problem — and how DVC solves it without replacing Git, just completing it.

---

## What This Repository Demonstrates

Traditional version control tracks code. Machine Learning requires tracking code, data, models, parameters, and metrics as a single interconnected system. This project shows how DVC extends Git to version the entire ML lifecycle, not just the source files.

Key concepts covered:

- Tracking large data files and model artifacts outside Git
- Defining reproducible ML pipelines as DAGs
- Running parameterized experiments without manual commits
- Rolling back to any prior experiment state in seconds
- Comparing metrics across multiple runs

```
├── dvc.yaml
├── params.yaml
├── requirements.txt
└── README.md
```

| Component | Purpose |
|---|---|
| `src/` | Modular pipeline stages: ingestion, preprocessing, feature engineering, model training, evaluation |
| `experiments/` | Jupyter notebooks for exploratory data analysis and prototyping |
| `dvc.yaml` | Pipeline definition as a Directed Acyclic Graph (DAG) |
| `params.yaml` | Centralized hyperparameter configuration |
| `data/` | Generated by the pipeline; tracked by DVC, ignored by Git |
| `models/` | Serialized model artifacts; tracked by DVC |
| `reports/` | Evaluation metrics output; consumed by DVC experiment tracking |

## Setup

Clone the repository and install dependencies:

```bash
git clone https://github.com/moksh-m9u/dvc-blog-tutorial.git
cd dvc-blog-tutorial
pip install -r requirements.txt
```

Initialize DVC:

```bash
dvc init
git add .dvc .dvcignore
git commit -m "Initialize DVC"
```

## Running the Pipeline

### Reproduce the full pipeline

```bash
dvc repro
```

This executes all stages defined in `dvc.yaml`: data ingestion, preprocessing, feature engineering, model building, and evaluation. DVC caches outputs automatically and skips stages that have not changed.

### Run as a tracked experiment

```bash
dvc exp run
```

This records the current state of `params.yaml`, the resulting `dvc.lock`, and the output metrics as a hidden experiment snapshot. No manual Git commit is required.

### View experiment history

```bash
dvc exp show
```

Displays a comparison table of all tracked experiments, their parameters, and their metrics side by side.

### Roll back to a specific experiment

```bash
dvc exp apply <experiment-id>
```

Restores the workspace to the exact parameter set, model artifact, and data state from that experiment.

### Promote a winner to a permanent branch

```bash
dvc exp branch <experiment-id> <branch-name>
git checkout <branch-name>
```

## Pipeline Parameters

All tunable values live in `params.yaml`:

```yaml
data_ingestion:
  test_size: 0.2

feature_engineering:
  max_features: 400

model_building:
  n_estimators: 900
  random_state: 2
```

Modify these values and run `dvc exp run` to generate a new tracked experiment. The pipeline will only re-execute stages affected by the parameter change.

## Why This Matters

In production ML systems, the question is never just "what code ran?" It is:

- Which dataset version produced this model?
- What preprocessing steps were active?
- What threshold yielded this precision-recall tradeoff?
- Can the entire pipeline be reproduced exactly six months from now?

DVC answers these questions by treating data, models, and metrics as first-class citizens in version control, alongside code.
